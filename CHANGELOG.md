# Changelog

## 0.1.0

First public release.

- `/jefe:jefe <task>` plans a job or a staged project: a scout looks, you answer a few questions, and one permission prompt (Go) approves the job's kinds of commands.
- Helpers on cheaper models build and review; the planner (your session's model) dispatches. You can choose the helper models at Go.
- The gate (`jefe-gate`) runs a size check, a secrets scan, your tests and the agreed checks, prints a fixed `report:` block, and can commit and push the tested commit when those kinds were approved.
- For Go the gate runs each module (a folder with `go.mod`) on its own and reads `go test -json`, so a nested module's failing test fails the gate, a failed test fails it even when `go test` exits 0 (a `TestMain` that calls `os.Exit(0)`), and a suite whose tests were all skipped is `tests: none found`, not a pass; pytest with only skipped tests is too. A check that exits 0 with a test runner's report of 0 passed and 0 failed prints `check: none found (<command>, ran no test)` and does not count as a check given, and a check that calls `go test` itself (also after `env NAME=value`) is read by its `-json` events as the suite is; one that reaches it through another program (`make test`, `sh -c`, a script) is not a pass when go test's own text (its package, coverage, verbose, benchmark or fuzz lines) is in its output, also behind a line prefix, since that text reads `ok` also when every test was skipped: it prints `check: none found (...)`, and the fix is to give the `go test` command itself as the check; a failure in that text (a failed test, a panic, a build or vet error) is `check: FAIL` although the program exits 0; a wrapper that hides or reformats that text (`go test -json`, gotestsum) is judged by its exit code, as any check is ([limits](docs/LIMITS.md)).
- A Stop hook sends the planner back once when its final message lacks the gate's `gate:` line, or carries another line stating a different verdict in one of two fixed forms; other wording is not caught ([limits](docs/LIMITS.md)).
- A permit hook answers only what Go approved; anything else is left to Claude Code. Approvals end with `allow --clear`, a new `go`, `park`, or 12 hours after Go, earlier once the last check has passed.
- Approvals in a file Jefe ignores (others could change it, or its `run/` folder is a symbolic link) are never reported as ended or as nothing active: `allow --clear`, `park` and an ending `finish` print `allowed: NOT ended` and exit 1, and a second `allow --clear` after the fix ends them; `go` and `start` in a home whose `run/` folder is a symbolic link name the fix.
- A `JEFE_HOME` inside the project folder is refused also when spelled in another Unicode normalisation (macOS names one folder by both) or reached by another path to the same folder (the gate compares device and inode; macOS's `/System/Volumes/Data`, `/.vol`, `/.nofollow` and `/.resolve` paths are refused by the status line too), and also by the project registry, so a shipped registry naming the folder cannot make its `.jefe/` look like this installation's.
- On macOS and Windows that inside-the-project test compares names the way a case-insensitive volume folds them (sharp s, ligatures, final sigma), not by lowercasing alone.
- A handoff file and a project registry let a fresh session continue; Jefe parks itself when context or plan usage runs high.
- A status line shows the phase and helpers and records cost, context and usage readings.
- Optional: text-only questions to an OpenAI-compatible provider you add; a benchmark harness with hidden tests. Its first results (one trial per task, run headless, on a slightly older plugin tree) are in [the README](README.md#the-numbers).
- Seen live: four runs on 2026-11-18 and 2026-11-19 (version 0.1.0, Claude Code 2.1.327 and 2.1.328, macOS terminal). Run D, ten scenarios on the code of this release: 59 checks passed, 5 failed, 1 did not apply; the five failures are one session where the planner did a three-line task directly instead of as a job, and that scenario passed 9 of 9 when run again alone. Runs A and C, ten scenarios each on earlier code: 65 checks passed, 0 failed in both. The Go prompt was the only permission prompt in every session that approved Go, in manual and auto mode. Run B, four scenarios between the two: 27 passed, 1 failed (the planner left the test suite out of Go, and the job reported it; the gate now prints `gate: PASS (tests not run)` for that case). One job ran in the desktop app and passed its gate ([details](docs/LIMITS.md#what-was-seen-live-and-what-was-not)). Not yet seen: Windows, an interactive job on Linux (the headless benchmark jobs ran on GitHub's Linux runners; the unit tests run there in CI), a foreground helper.
